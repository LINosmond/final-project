# 研究靶機（research-demo）

一個**你自己掌控的本機模擬註冊頁**，用來研究「表單自動填單」與「自動化偵測」，
不連任何外部網站、資料只留在你瀏覽器的 localStorage。適合當論文/報告的可重現實驗環境。

## 檔案

| 檔案 | 說明 |
|------|------|
| `mock_register.html` | 模擬註冊表單（帳號／密碼／信箱＋「我不是機器人」＋送出）＋ 自動化偵測儀表 |

## 怎麼開始

**最簡單**：直接用瀏覽器打開 `mock_register.html` 就能用。

想模擬「腳本/外掛從外部填字」的情境（例如測 Tampermonkey），用本機伺服器開，
讓它有 `http://` 網址：

```
cd account-creator/research-demo
python -m http.server 8000
# 瀏覽器開 http://localhost:8000/mock_register.html
```

## 兩種操作，做對照組

1. **人手輸入**：自己逐格打字 → 勾「我不是機器人」→ 按「註冊」。
2. **程式填入（模擬 bot）**：按「模擬自動填入（bot）」讓程式直接塞值 → 勾選 → 按「註冊」。

每按一次「註冊」，右側儀表就記一筆，並判定 `human` 或 `bot`。

## 偵測邏輯（研究重點）

頁面會監聽每個欄位的 `keydown` / `paste` / `input` / `focus`，累積這些特徵並算出 bot 分數：

| 訊號 | 意義 | 加權 |
|------|------|------|
| 值憑空出現（有 input 但零 keydown、零 paste） | 典型程式塞值 | +30 |
| 有值卻完全沒擊鍵 | 非人手輸入 | +10 |
| 聚焦到填完 < 30ms | 人手做不到的速度 | +8 |
| 整張表單零擊鍵 | 全自動 | +20 |

分數 ≥ 40 判為 `bot`。**權重與門檻都在 `mock_register.html` 的 `scoreBot()` 裡，可自行調整**，
用來研究「不同填值方式（原生 setter／模擬按鍵／貼上）能不能被偵測」。

## 匯出數據

按「匯出 CSV」下載 `detect_log.csv`（欄位：time, account, verdict, score, keys, pastes, minFillMs），
可直接丟進試算表或 pandas 做統計、畫圖。

## 研究方向舉例

- 比較「原生 value setter＋dispatch event」與「逐鍵 typewrite」在偵測上的差異
- 加入滑鼠軌跡、輸入間隔分布等特徵，看能不能降低誤判
- 反過來研究「怎樣的自動填單最難被偵測」，作為防禦方調整偵測規則的依據

以上都在**你自己的頁面**上做，資料自產自用，可重現、可公開，不涉及任何第三方服務。
