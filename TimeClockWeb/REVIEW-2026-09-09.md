# 打卡與薪資流程檢查（2026-09-09）

本次修正：薪資工時直接使用最新考勤，移除手動帶入操作。舊月資料即使曾存固定工時，也以考勤重新計算；金額設定仍取該月保存值。月薪制固定工作 1、加班 0。這會使過去月份在補登或刪除打卡後重新計算，不再把「儲存薪資」視為工時鎖定。

## 已修正與驗證

- 薪資頁、總表列印及 CSV 使用相同的有效薪資與金額計算函式。
- 頁面開著時，補登、刪除、假日覆寫會即時影響工時與金額，不清除未儲存的獎金／扣款。
- 工時唯讀且每次由考勤推導；儲存的工時為 null，保持現有後端 JSON 格式相容。
- 薪資寫入成功後才顯示成功；失敗保留原薪資與表單輸入，可重試。儲存中避免重複送出及列印舊資料。
- 修正薪資同步等待超時後未解除、可能永久停止接收遠端薪資更新的問題。
- 考勤合計包含加班倍率，薪資分列基本工時及加班工時，各乘各自單價；不能直接把加權合計塞入基本工時。
- 加入 `npm test` 並在 GitHub Pages 建置前執行。

9 組自動化測試涵蓋舊結算、補登／刪除／空月份、員工與月份隔離、假日與加班、月薪相容、React 輪詢更新與輸入保留、儲存及重複點擊、列印 HTML／CSV、後端打卡去重、薪資與備份格式往返、申請審核及 API key 拒絕。後端測試使用記憶體模擬試算表，沒有修改正式員工資料。

## 整體檢查仍發現的既有問題

以下未在本次薪資修正中改動，不能宣稱整套系統已無缺陷：

1. **後端身分驗證不足**：管理員驗證與登入狀態主要在前端，Apps Script 只有共用 API key，且金鑰會隨前端公開。員工、薪資及管理操作缺少伺服器端角色驗證。需另做真正的登入與授權機制。
2. **多裝置整包覆寫**：薪資、管理員補登及部分員工管理仍以整包 `set` 保存。兩個管理員或補登與員工打卡同時發生，可能由較舊資料覆蓋另一方更新；伺服器鎖不能解決客戶端舊快照。本次只阻擋同一頁面的重複薪資寫入，跨裝置應改為伺服器單筆更新或版本衝突檢查。
3. **後端輸入檢查不足**：`set punches` 解析失敗會當成空陣列；缺少結構驗證。修正需要同步更新已部署 Apps Script。備份還原與補登應加上結構及時段驗證。
4. **其他儲存操作的成功提示**：員工新增／刪除與補登等仍有先更新画面或捕捉錯誤後繼續報成功的情況，需另行統一錯誤處理。薪資部分已修正。
5. **建置工具依賴**：安裝時 npm 報告 6 項依賴弱點（2 moderate、4 high）。未直接套用可能破壞相容性的全面升級；需要獨立評估更新。

## 驗證界線

- 沒有對正式帳號執行新增、補登、薪資寫入或備份還原。
- 沒有用實體 HP 印表機測試 A4 邊界；本次只驗證列印輸出的工時與薪資來源。
- 現有獨立申報快照不是即時考勤資料，本次未修改其生成、固定或列印流程。
- Apps Script 線上部署版本未經重新發布；後端測試以 repository 內的程式為準。
