# 登入恢復與載入流程修正

原問題：員工從手機主畫面捷徑重新開啟時，必須先等所有共用資料讀完；若首次名單為空，程式會永久放棄本次登入還原。慢請求也會被每六秒啟動的新輪詢疊加。

## 修正

- 先讀取裝置保存的登入。員工名單缺漏時保留帳號，顯示待確認與重試，取得正確名單後自動恢復；確認前不能打卡。主動登出仍會清除登入，遲到回應不能登入其他帳號。
- 未登入只讀員工名單，立即顯示登入表單。員工不再下載薪資、申報資料；管理員保留完整資料。
- 所有同步入口共用一個進行中的請求；每輪完成後等待 30 秒再讀，背景暫停，回到前景立即讀取。切換帳號會等待舊請求完成後立刻讀取新帳號資料，並忽略舊身分回應。
- 每個請求 20 秒逾時；暫時失敗的讀取及後端可去重操作最多重試一次。永久錯誤與破損資料不重試。只有明確不支援 getAll 的舊後端才逐項相容讀取。
- 不把不完整或破損回應當成空員工表。網路失敗保留已確認資料並提供重試。
- 審核結果不明時不再整包覆寫員工或誤報成功。裝置無法保存登入時持續顯示提醒。

## 驗證

- `npm test`：34 / 34 通過，包含 15 項登入與同步測試、10 項網路測試，以及原有薪資與後端模擬測試。
- `npm run build` 與 `git diff --check` 通過。
- 使用 `npm run dev` 下的 `tests/browser.html` 與虛構員工，在 390 × 844 瀏覽器畫面檢查待確認、恢復登入及斷線提示；首次空名單後已實際看到自動恢復打卡畫面。
- 沒有以正式員工建立帳號或打卡，沒有修改考勤／薪資資料；未重新部署 Apps Script。

## 範圍

此次修正前端排程、資料分流與登入恢復。Apps Script 仍使用既有後端及完整歷史考勤格式，因此實際網路／Google 服務延遲仍可能影響首次讀取；未宣稱已量測所有員工手机的實際速度或重現每一次真實事故。

原網站網址維持 https://linosmond.github.io/final-project/ 。員工應關閉既有頁面後重新開啟，必要時重新整理一次以載入新版；不需要清除網站資料。
